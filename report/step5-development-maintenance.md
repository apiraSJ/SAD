## 5.1 Test Plan & Test Cases

### แผนการทดสอบ (Test Plan)

การทดสอบระบบมุ่งเน้นการตรวจสอบว่าระบบสามารถทำงานได้ตรงตามความต้องการของผู้ใช้และข้อกำหนดของระบบ โดยแบ่งการทดสอบออกเป็น 3 ระดับ ได้แก่

1. **Unit Testing** — ทดสอบฟังก์ชันย่อยแต่ละส่วนว่าทำงานถูกต้อง
2. **Integration Testing** — ทดสอบการเชื่อมต่อระหว่างฟังก์ชันและโมดูล
3. **User Acceptance Testing (UAT)** — ทดสอบโดยผู้ใช้จริงเพื่อยอมรับระบบ

**กลุ่มผู้ทดสอบ:**
- นักเรียนนายเรืออากาศ (กลุ่มผู้ใช้หลัก) — ทดสอบการแจ้งปัญหาและติดตามสถานะ
- ผู้ดูแลอาคาร — ทดสอบการรับเรื่อง มอบหมายงาน และตั้งค่าระบบ
- ช่างซ่อม — ทดสอบการรับงาน บันทึกผลซ่อม/ค่าใช้จ่าย และปิดงาน

**เกณฑ์การยอมรับ (Acceptance Criteria):**
- ระบบทุกฟังก์ชันทำงานได้ตรงตาม Use Case
- ไม่มีข้อผิดพลาดร้ายแรง (Critical Bug) ที่ทำให้ระบบไม่สามารถใช้งานได้
- ผู้ใช้ทดสอบสามารถใช้งานระบบได้โดยไม่ต้องมีผู้สอน
- เวลาตอบสนองของหน้าจอไม่เกิน 3 วินาที

## 5.3 System Maintenance Plan

### ประเภทการบำรุงรักษา

| ประเภท | คำอธิบาย | ตัวอย่าง | ความถี่ |
| --- | --- | --- | --- |
| **Corrective Maintenance** | แก้ไขข้อผิดพลาดและ Bug ที่พบหลังใช้งาน | แก้ไขหน้าจอแสดงผลผิด, แก้ไขคำนวณค่าใช้จ่ายผิด | ตามปัญหาที่เกิดขึ้น |
| **Adaptive Maintenance** | ปรับระบบให้เข้ากับสภาพแวดล้อมใหม่ | อัปเดต PHP/Web Server, ปรับ Database Schema | ทุก 6 เดือน |
| **Perfective Maintenance** | ปรับปรุงประสิทธิภาพและเพิ่มฟังก์ชันใหม่ | เพิ่มระบบ Push Notification, ปรับ UI ให้สวยงามขึ้น | ทุก 3-6 เดือน |
| **Preventive Maintenance** | ป้องกันปัญหาที่อาจเกิดขึ้นในอนาคต | สำรองข้อมูลอัตโนมัติ, ตรวจสอบ Security Patch, ตรวจสอบ Performance | รายสัปดาห์/รายเดือน |

### แผนการบำรุงรักษา

| กิจกรรม | รายละเอียด | ความถี่ | ผู้รับผิดชอบ |
| --- | --- | --- | --- |
| สำรองข้อมูลฐานข้อมูล (Backup) | สำรองข้อมูลอัตโนมัติแบบ Daily | ทุกวัน | ธัญศิษฏ์ |
| ตรวจสอบ Server Logs | ตรวจสอบ Log ปัญหาและการใช้งาน | รายสัปดาห์ | อภิรักษ์ |
| อัปเดต Security Patch | ตรวจสอบและติดตั้ง Security Update | รายเดือน | ธัญศิษฏ์ |
| ตรวจสอบ Performance | วิเคราะห์ความเร็วและการใช้ทรัพยากร | รายเดือน | อภิรักษ์ |
| ทดสอบระบบ (Regression Test) | ทดสอบฟังก์ชันหลักหลังการอัปเดต | ทุกครั้งหลังแก้ไข | ทั้งทีม |
| รวบรวม Feedback จากผู้ใช้ | รับฟังปัญหาและข้อเสนอแนะจากผู้ใช้ | รายเดือน | กฤตเมธ |
| ปรับปรุง UI/UX | ปรับหน้าจอตาม Feedback ของผู้ใช้ | ทุก 3 เดือน | กฤตเมธ |

## 5.4 Strategy for System Upgrade

### แผนการพัฒนาระบบในอนาคต

การอัปเกรดระบบจะดำเนินการเป็นระยะ โดยพิจารณาจากความต้องการของผู้ใช้ ข้อจำกัดด้านทรัพยากร และเทคโนโลยีที่เหมาะสม

### ระยะสั้น (0-6 เดือนหลังเปิดใช้งาน)

| การอัปเกรด | รายละเอียด | วัตถุประสงค์ |
| --- | --- | --- |
| **Push Notification** | เพิ่มการแจ้งเตือนแบบ Push ผ่าน Web Browser หรือ Mobile | ผู้ใช้ได้รับการแจ้งเตือนทันทีเมื่อสถานะเปลี่ยน |
| **ระบบค้นหาขั้นสูง** | เพิ่มความสามารถในการค้นหาและกรองข้อมูล | ค้นหาและดูข้อมูลได้สะดวกขึ้น |
| **ปรับปรุง UI/UX** | ปรับหน้าจอตาม Feedback จากผู้ใช้จริง | ใช้งานง่ายและสวยงามขึ้น |

### ระยะกลาง (6-12 เดือน)

| การอัปเกรด | รายละเอียด | วัตถุประสงค์ |
| --- | --- | --- |
| **Mobile Application** | พัฒนาเป็น Native App (Android/iOS) หรือ PWA | ใช้งานสะดวกบนมือถือ |
| **ระบบรายงานขั้นสูง** | เพิ่ม Dashboard แบบ Interactive พร้อม Export PDF/Excel | วิเคราะห์ข้อมูลได้ละเอียดขึ้น |
| **ระบบถ่ายโอนข้อมูล** | สร้าง API สำหรับเชื่อมต่อกับระบบอื่น | แลกเปลี่ยนข้อมูลกับระบบภายนอก |

### ระยะยาว (1-2 ปี)

| การอัปเกรด | รายละเอียด | วัตถุประสงค์ |
| --- | --- | --- |
| **AI Predictive Maintenance** | ใช้ AI วิเคราะห์ข้อมูลเพื่อทำนายปัญหาที่อาจเกิด | ป้องกันปัญหาก่อนเกิด |
| **Integration กับระบบบริหารอาคาร** | เชื่อมต่อกับระบบ CMMS หรือ ERP ของหน่วยงาน | บริหารจัดการอาคารอย่างครบวงจร |
| **Multi-Building Support** | ขยายระบบไปใช้กับอาคารอื่นของหน่วยงาน | ครอบคลุมทุกอาคาร |
| **ระบบประเมินความพึงพอใจ** | เพิ่มแบบสำรวจความพึงพอใจหลังการซ่อม | วัดประสิทธิภาพการให้บริการ |

### หลักการอัปเกรด

1. **User-Involving Modifications** — การปรับปรุงทุกครั้งต้องรับฟัง Feedback จากผู้ใช้จริง
2. **Backward Compatibility** — การอัปเกรดต้องไม่ทำให้ข้อมูลเดิมสูญหาย
3. **Testing Before Deployment** — ทดสอบทุกครั้งก่อนนำขึ้น Server จริง
4. **Documentation** — บันทึกการเปลี่ยนแปลงทุกครั้ง (Changelog)
5. **Rollback Plan** — เตรียมแผนกลับสู่เวอร์ชันเดิมกรณีมีปัญหา
