## 3.1 Context Diagram

Context Diagram แสดงขอบเขตของระบบและความสัมพันธ์กับหน่วยงานภายนอก

```
                        ┌─────────────────────────────────┐
                        │                                 │
   แจ้งปัญหา/             │                                 │       แจ้งเตือนสถานะ/
   ติดตามสถานะ           │                                 │       ผลการซ่อม
  ┌──────────┐           │                                 │          ┌──────────┐
  │  นักเรียน  │ ────────►│                                 │ ────────►│  นักเรียน  │
  │นายเรืออากาศ│          │                                 │          │นายเรืออากาศ│
  └──────────┘           │                                 │          └──────────┘
                         │                                 │
                         │    ระบบแจ้งซ่อมอาคารนอน        │
                         │   (Barracks Repair Request      │
                         │         System)                 │
                         │                                 │
                         │                                 │
  ┌──────────┐           │                                 │          ┌──────────┐
  │ ผู้ดูแล  │ ────────►│                                 │ ────────►│  ช่าง    │
  │  อาคาร   │           │                                 │          │  ซ่อม    │
  └──────────┘           │                                 │          └──────────┘
                         │                                 │

```

**รายละเอียดข้อมูลที่แลกเปลี่ยนกับหน่วยงานภายนอก**

| หน่วยงานภายนอก | ข้อมูลขาเข้า (Input) สู่ระบบ | ข้อมูลขาออก (Output) จากระบบ |
| --- | --- | --- |
| **นักเรียนนายเรืออากาศ** | แจ้งปัญหา (อาคาร, ห้อง, ประเภท, รายละเอียด, รูปภาพ) | แจ้งเตือนสถานะ, ผลการซ่อม, เลขที่ใบแจ้งซ่อม |
| **ผู้ดูแลอาคาร** | รับเรื่อง, มอบหมายช่าง, อนุมัติการซ่อม | รายการแจ้งซ่อมใหม่, รายงานสรุป, สถานะงาน |
| **ช่างซ่อม** | บันทึกผลการซ่อม, ค่าใช้จ่าย, สถานะงาน | รายการงานที่ได้รับมอบหมาย, รายละเอียดปัญหา |
| **ผู้บังคับบัญชา / ฝ่ายธุรการ** | สอบถามข้อมูลรายงาน (Query) | รายงานสรุปสถิติ, รายงานค่าใช้จ่าย |

**คำอธิบาย Process ใน DFD Level-1**

| 1.0 | ยืนยันตัวตนและจัดการโปรไฟล์ (Authen & Manage Profile) | User | ตรวจสอบสิทธิ์การเข้าสู่ระบบและการจัดการข้อมูลผู้ใช้ (User) |
| 2.0 | สร้างคำขอแจ้งซ่อม (Create Repair Request) | RepairRequest | รับข้อมูลการแจ้งซ่อมจากนักเรียน บันทึกรายการ และส่งแจ้งเตือนผู้ดูแลอาคาร |
| 3.0 | มอบหมายงานซ่อม (Assign Repair Task) | Repair | ผู้ดูแลอาคารรับเรื่องและมอบหมายงานให้ช่าง พร้อมสร้างบันทึกงานซ่อม (Repair) |
| 4.0 | บันทึกผลการซ่อม ค่าใช้จ่าย และปิดงาน (Record Cost & Close Job) | Expense | ช่างบันทึกผลการซ่อมและค่าใช้จ่าย (Expense) เมื่อซ่อมเสร็จ |
| 5.0 | ออกรายงานซ่อมบำรุง (Generate Maintenance Report) | - | สรุปสถิติและงบประมาณการซ่อมบำรุงจากข้อมูล Repair/Expense ให้ผู้บังคับบัญชา |

## 3.3 Process Description

### Process 1.0: ยืนยันตัวตนและจัดการโปรไฟล์ (Authen & Manage Profile)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | ตรวจสอบสิทธิ์ผู้ใช้เมื่อเข้าสู่ระบบ (Login) และจัดการข้อมูลบัญชีผู้ใช้ตามบทบาท |
| **Input** | ชื่อผู้ใช้, รหัสผ่าน, ข้อมูลโปรไฟล์, บทบาท (Role) |
| **Output** | Token การเข้าสู่ระบบ, ข้อมูลผู้ใช้ที่ถูกต้องตามบทบาท |
| **Process** | 1. รับชื่อผู้ใช้และรหัสผ่าน 2. ตรวจสอบสิทธิ์ (Authen) 3. ดึงข้อมูลบทบาท 4. จัดการข้อมูลโปรไฟล์ 5. บันทึก/อัปเดตข้อมูล User |

### Process 2.0: สร้างคำขอแจ้งซ่อม (Create Repair Request)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | รับข้อมูลการแจ้งซ่อมจากนักเรียน สร้างรายการ RepairRequest และส่งแจ้งเตือนผู้ดูแลอาคาร |
| **Input** | อาคาร, ห้อง, ประเภทปัญหา, รายละเอียด, รูปภาพ, ความเร่งด่วน |
| **Output** | เลขที่ใบแจ้งซ่อม, ข้อมูลแจ้งซ่อมที่บันทึกแล้ว, แจ้งเตือนไปยังผู้ดูแลอาคาร |
| **Process** | 1. รับข้อมูลจากฟอร์มแจ้งปัญหา 2. ตรวจสอบความครบถ้วน 3. สร้างเลขที่ใบแจ้งซ่อมอัตโนมัติ 4. บันทึกลง RepairRequest 5. ส่งแจ้งเตือนผู้ดูแลอาคาร |

### Process 3.0: มอบหมายงานซ่อม (Assign Repair Task)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | ผู้ดูแลอาคารตรวจสอบรายการที่รับเรื่องแล้ว เลือกช่าง และสร้างบันทึกงานซ่อม Repair |
| **Input** | รายการแจ้งซ่อมที่รับเรื่องแล้ว, การเลือกรายการช่าง |
| **Output** | บันทึกงานซ่อม (Repair), แจ้งเตือนไปยังช่างที่ได้รับมอบหมาย |
| **Process** | 1. ตรวจสอบรายการแจ้งซ่อมที่เข้ามา 2. รับเรื่อง 3. เลือกช่างที่เหมาะสม 4. สร้างบันทึก Repair และมอบหมายงาน 5. แจ้งเตือนช่าง |

### Process 4.0: บันทึกผลการซ่อม ค่าใช้จ่าย และปิดงาน (Record Cost & Close Job)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | ช่างบันทึกผลการซ่อม รายการอะไหล่/ค่าใช้จ่ายลง Expense และปิดงานเมื่อซ่อมเสร็จ |
| **Input** | ผลการซ่อม, รายการอะไหล่, จำนวน, ราคาต่อหน่วย, ค่าแรง |
| **Output** | บันทึกค่าใช้จ่าย (Expense), สถานะเปลี่ยนเป็น "ซ่อมเสร็จ" |
| **Process** | 1. เปิดงานที่ได้รับมอบหมาย 2. บันทึกผลการซ่อม 3. บันทึกรายการค่าใช้จ่ายลง Expense 4. กดปิดงาน 5. ส่งแจ้งเตือนสถานะ "ซ่อมเสร็จ" ไปยังผู้แจ้ง |

### Process 5.0: ออกรายงานซ่อมบำรุง (Generate Maintenance Report)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | รวบรวมข้อมูลจาก Repair และ Expense เพื่อสร้างรายงานสรุปสถิติและงบประมาณ |
| **Input** | เงื่อนไขการรายงาน (ช่วงเวลา, ประเภท, อาคาร) |
| **Output** | รายงานสรุปสถิติการซ่อม, รายงานค่าใช้จ่าย, รายงานแยกตามประเภท/อาคาร/ช่วงเวลา |
| **Process** | 1. รับเงื่อนไขการรายงาน 2. ดึงข้อมูลจาก Repair/Expense ตามเงื่อนไข 3. ประมวลผลสถิติ 4. จัดรูปแบบรายงาน 5. ส่งรายงานให้ผู้บังคับบัญชา |

### แผนภาพความสัมพันธ์ (Relationship Summary)

## 3.5 Data Dictionary

รายละเอียดข้อมูลของแต่ละ Entity ตาม ER2cadet.xml (8 ตารางหลัก)

### Table: User (ผู้ใช้งาน / ผู้แจ้ง)

| ชื่อฟิลด์ | ชนิดข้อมูล | ขนาด | Key | คำอธิบาย |
| --- | --- | --- | --- | --- |
| user_id | INT | - | PK | รหัสผู้ใช้ (Auto Increment) |
| name | VARCHAR | 100 | - | ชื่อ-นามสกุล |
| rank | VARCHAR | 50 | - | ยศ (เช่น นักเรียนนายเรืออากาศ) |
| email | VARCHAR | 100 | - | อีเมล |
| username | VARCHAR | 50 | UQ | ชื่อผู้ใช้สำหรับเข้าสู่ระบบ |
| password | VARCHAR | 255 | - | รหัสผ่าน (Hashed) |
| role | ENUM | - | - | บทบาท: Cadet, Admin, Tech, Exec |

### Table: Building (อาคาร)

| ชื่อฟิลด์ | ชนิดข้อมูล | ขนาด | Key | คำอธิบาย |
| --- | --- | --- | --- | --- |
| building_id | INT | - | PK | รหัสอาคาร (Auto Increment) |
| building_name | VARCHAR | 100 | - | ชื่ออาคาร (เช่น อาคาร A, อาคาร B) |
| description | TEXT | - | - | รายละเอียดอาคาร |

### Table: Room (ห้อง)

| ชื่อฟิลด์ | ชนิดข้อมูล | ขนาด | Key | คำอธิบาย |
| --- | --- | --- | --- | --- |
| room_id | INT | - | PK | รหัสห้อง (Auto Increment) |
| building_id | INT | - | FK | รหัสอาคาร (เชื่อมต่อ Building) |
| floor | INT | - | - | ชั้นที่ |
| room_number | VARCHAR | 10 | - | หมายเลขห้อง (เช่น 101, 205) |

### Table: RepairRequest (รายการแจ้งซ่อม)

| ชื่อฟิลด์ | ชนิดข้อมูล | ขนาด | Key | คำอธิบาย |
| --- | --- | --- | --- | --- |
| request_id | VARCHAR | 20 | PK | รหัสรายการแจ้งซ่อม (เช่น REP-0001) |
| user_id | INT | - | FK | รหัสผู้แจ้ง (เชื่อมต่อ User) |

### Use Case Description

#### UC-01: เข้าสู่ระบบ (Login)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-01 |
| **ชื่อ Use Case** | เข้าสู่ระบบ (Login) |
| **Actor** | ผู้ใช้ทุกคน |
| **Precondition** | ผู้ใช้มีบัญชีในระบบ |
| **Postcondition** | เข้าสู่ระบบสำเร็จ แสดงหน้าหลักตามบทบาท |
| **Main Flow** | 1. ผู้ใช้กรอกชื่อผู้ใช้และรหัสผ่าน 2. ระบบตรวจสอบความถูกต้อง 3. แสดงหน้าหลักตามบทบาท |
| **Alternative Flow** | ชื่อผู้ใช้หรือรหัสผ่านผิด → แสดงข้อความแจ้งเตือน |

#### UC-02: แจ้งปัญหา (Submit Repair Request)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-02 |
| **ชื่อ Use Case** | แจ้งปัญหา (Submit Repair Request) |
| **Actor** | นักเรียนนายเรืออากาศ |
| **Precondition** | ผู้ใช้เข้าสู่ระบบแล้ว |
| **Postcondition** | บันทึกการแจ้งปัญหาสำเร็จ สร้างเลขที่ใบแจ้งซ่อม |
| **Main Flow** | 1. เลือกอาคารและห้อง 2. เลือกประเภทปัญหา 3. กรอกรายละเอียด 4. แนบรูปภาพ 5. ยืนยันการแจ้ง 6. ระบบสร้างเลขที่ใบแจ้งซ่อมและบันทึก |
| **Alternative Flow** | ข้อมูลไม่ครบถ้วน → แสดงข้อความแจ้งเตือนให้กรอกข้อมูลเพิ่ม |

#### UC-03: ติดตามสถานะ (Track Status)

| รายการ | รายละเอียด |
| --- | --- |

| **Precondition** | ผู้ใช้เข้าสู่ระบบแล้ว มีรายการแจ้งซ่อม |
| **Postcondition** | แสดงสถานะปัจจุบันของงานซ่อม |
| **Main Flow** | 1. เข้าสู่หน้ารายการแจ้งซ่อมของฉัน 2. เลือกรายการที่ต้องการ 3. แสดงสถานะและรายละเอียด |

#### UC-05: รับ/ปฏิเสธแจ้งซ่อม (Accept/Reject Request)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-05 |
| **ชื่อ Use Case** | รับ/ปฏิเสธแจ้งซ่อม (Accept/Reject Request) |
| **Actor** | ผู้ดูแลอาคาร |
| **Precondition** | มีรายการแจ้งซ่อมใหม่ที่ยังไม่ได้ตรวจสอบ |
| **Postcondition** | สถานะรายการเปลี่ยนเป็น "รับเรื่อง" หรือ "ปฏิเสธ" |
| **Main Flow** | 1. ดูรายการแจ้งซ่อมใหม่ 2. ตรวจสอบรายละเอียด 3. คัดกรองปัญหาซ้ำซ้อน 4. รับเรื่องหรือปฏิเสธ 5. บันทึกผลการตรวจสอบ |

#### UC-06: มอบหมายช่าง (Assign Technician)

| รายการ | รายละเอียด |

| **Postcondition** | ช่างได้รับมอบหมายงาน สถานะเปลี่ยนเป็น "มอบหมายแล้ว" |
| **Main Flow** | 1. เลือกรายการแจ้งซ่อมที่รับเรื่องแล้ว 2. เลือกช่างที่เหมาะสม 3. ยืนยันการมอบหมาย 4. แจ้งเตือนไปยังช่าง |

| **Postcondition** | บันทึกผลการซ่อมและวัสดุที่ใช้เรียบร้อย ยังไม่เปลี่ยนสถานะจนกว่าจะปิดงาน |
