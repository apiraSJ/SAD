## 3.1 Context Diagram

Context Diagram แสดงขอบเขตของระบบและความสัมพันธ์กับหน่วยงานภายนอก

```
                        ┌─────────────────────────────────┐
                        │                                 │
   แจ้งปัญหา/             │                                 │       แจ้งเตือนสถานะ/
   ติดตามสถานะ           │                                 │       ผลการซ่อม
  ┌──────────┐           │                                 │          ┌──────────┐
  │  นักเรียน  │ ────────►│                                 │ ────────►│  นักเรียน  │
  │นายเรืออากาศ│          │                                 │          │นายเรืออากาศ│
  └──────────┘           │                                 │          └──────────┘
                         │                                 │
                         │    ระบบแจ้งซ่อมอาคารนอน        │
                         │   (Barracks Repair Request      │
                         │         System)                 │
                         │                                 │
                         │                                 │
  ┌──────────┐           │                                 │          ┌──────────┐
  │ ผู้ดูแล  │ ────────►│                                 │ ────────►│  ช่าง    │
  │  อาคาร   │           │                                 │          │  ซ่อม    │
  └──────────┘           │                                 │          └──────────┘
                         │                                 │
                         └─────────────────────────────────┘
```

**รายละเอียดข้อมูลที่แลกเปลี่ยนกับหน่วยงานภายนอก**

| หน่วยงานภายนอก | ข้อมูลขาเข้า (Input) สู่ระบบ | ข้อมูลขาออก (Output) จากระบบ |
| --- | --- | --- |
| **นักเรียนนายเรืออากาศ** | แจ้งปัญหา (อาคาร, ห้อง, ประเภท, รายละเอียด, รูปภาพ) | แจ้งเตือนสถานะ, ผลการซ่อม, เลขที่ใบแจ้งซ่อม |
| **ผู้ดูแลอาคาร** | รับเรื่อง, มอบหมายช่าง, อนุมัติการซ่อม | รายการแจ้งซ่อมใหม่, รายงานสรุป, สถานะงาน |
| **ช่างซ่อม** | บันทึกผลการซ่อม, ค่าใช้จ่าย, สถานะงาน | รายการงานที่ได้รับมอบหมาย, รายละเอียดปัญหา |
| **ผู้บังคับบัญชา / ฝ่ายธุรการ** |  запрос (Query) ข้อมูลรายงาน | รายงานสรุปสถิติ, รายงานค่าใช้จ่าย |

**คำอธิบาย Process ใน DFD Level-1**

| Process | ชื่อ Process | คำอธิบายโดยย่อ |
| --- | --- | --- |
| 1.0 | จัดการแจ้งซ่อม | รับข้อมูลการแจ้งปัญหาจากนักเรียน บันทึกข้อมูล และส่งต่อให้ผู้ดูแลอาคาร |
| 2.0 | จัดการงานซ่อม | รับเรื่อง มอบหมายช่าง ติดตามสถานะ และบันทึกผลการซ่อม |
| 3.0 | จัดการผู้ใช้ | จัดการข้อมูลผู้ใช้ สิทธิ์การใช้งาน และการเข้าสู่ระบบ |
| 4.0 | จัดการข้อมูลและรายงาน | รวบรวมข้อมูลและออกรายงานสถิติการซ่อมและค่าใช้จ่าย |
| 5.0 | จัดการข้อมูลอ้างอิง | จัดการข้อมูลอาคาร ห้อง ประเภทปัญหา และวัสดุอุปกรณ์ |

## 3.3 Process Description

### Process 1.0: จัดการแจ้งซ่อม (Manage Repair Request)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | รับและบันทึกข้อมูลการแจ้งปัญหาจากนักเรียนนายเรืออากาศ ตรวจสอบความถูกต้อง และสร้างรายการแจ้งซ่อมใหม่ |
| **Input** | ข้อมูลผู้แจ้ง, อาคาร, ห้อง, ประเภทปัญหา, รายละเอียด, รูปภาพประกอบ |
| **Output** | เลขที่ใบแจ้งซ่อม, ข้อมูลแจ้งซ่อมที่บันทึกแล้ว, แจ้งเตือนไปยังผู้ดูแลอาคาร |
| **Process** | 1. รับข้อมูลจากฟอร์มแจ้งปัญหา 2. ตรวจสอบความครบถ้วนของข้อมูล 3. สร้างเลขที่ใบแจ้งซ่อมอัตโนมัติ 4. บันทึกข้อมูลลงฐานข้อมูล 5. ส่งแจ้งเตือนไปยังผู้ดูแลอาคาร |

### Process 2.0: จัดการงานซ่อม (Manage Repair Job)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | ตรวจสอบรายการแจ้งซ่อม รับเรื่อง มอบหมายงานให้ช่าง ติดตามสถานะ และบันทึกผลการซ่อม |
| **Input** | รายการแจ้งซ่อมใหม่, การรับเรื่อง/ปฏิเสธ, การมอบหมายช่าง, ผลการซ่อม, ค่าใช้จ่าย |
| **Output** | สถานะงานที่อัปเดต, แจ้งเตือนไปยังผู้แจ้ง, ข้อมูลผลการซ่อม |
| **Process** | 1. ตรวจสอบรายการแจ้งซ่อมที่เข้ามา 2. คัดกรองปัญหาซ้ำซ้อน 3. รับเรื่องและเปลี่ยนสถานะ 4. เลือกช่างที่เหมาะสมและมอบหมายงาน 5. บันทึกผลการซ่อมและค่าใช้จ่าย 6. ปิดงาน 7. ส่งแจ้งเตือนสถานะไปยังผู้แจ้ง |

### Process 3.0: จัดการผู้ใช้ (Manage User)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | จัดการข้อมูลผู้ใช้ สิทธิ์การใช้งาน และการยืนยันตัวตน |
| **Input** | ข้อมูลผู้ใช้ใหม่, การแก้ไขข้อมูล, การกำหนดสิทธิ์, ชื่อผู้ใช้/รหัสผ่าน |
| **Output** | ข้อมูลผู้ใช้ที่จัดการแล้ว, Token การเข้าสู่ระบบ, สิทธิ์การใช้งาน |
| **Process** | 1. ตรวจสอบและยืนยันตัวตนผู้ใช้ 2. ดึงข้อมูลสิทธิ์ตามบทบาท 3. จัดการข้อมูลผู้ใช้ (เพิ่ม/แก้ไข/ลบ) 4. กำหนดสิทธิ์การเข้าถึงแต่ละฟังก์ชัน |

### Process 4.0: จัดการข้อมูลและรายงาน (Manage Data & Report)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | รวบรวมข้อมูลจากฐานข้อมูลเพื่อสร้างรายงานสถิติและค่าใช้จ่าย |
| **Input** | เงื่อนไขการรายงาน (ช่วงเวลา, ประเภท, อาคาร), คำขอ Query |
| **Output** | รายงานสรุปสถิติการซ่อม, รายงานค่าใช้จ่าย, รายงานแยกตามประเภท/อาคาร/ช่วงเวลา |
| **Process** | 1. รับเงื่อนไขการรายงาน 2. ดึงข้อมูลจากฐานข้อมูลตามเงื่อนไข 3. ประมวลผลและคำนวณสถิติ 4. จัดรูปแบบรายงาน 5. ส่งรายงานให้ผู้ร้องขอ |

### Process 5.0: จัดการข้อมูลอ้างอิง (Manage Reference Data)

| รายการ | รายละเอียด |
| --- | --- |
| **คำอธิบาย** | จัดการข้อมูลพื้นฐานที่ใช้ในระบบ เช่น ข้อมูลอาคาร ห้อง ประเภทปัญหา วัสดุอุปกรณ์ |
| **Input** | ข้อมูลอาคาร, ข้อมูลห้อง, ประเภทปัญหา, วัสดุอุปกรณ์ |
| **Output** | ข้อมูลอ้างอิงที่อัปเดตแล้ว สำหรับใช้ในฟอร์มแจ้งปัญหาและการรายงาน |
| **Process** | 1. รับข้อมูลจากผู้ดูแลระบบ 2. ตรวจสอบความถูกต้อง 3. บันทึก/แก้ไข/ลบข้อมูลอ้างอิง 4. ตรวจสอบความสัมพันธ์ของข้อมูล |

## 3.5 Data Dictionary

รายละเอียดข้อมูลของแต่ละ Entity (ตารางหลัก)

### Table: Users (ผู้ใช้)

| ชื่อฟิลด์ | ชนิดข้อมูล | ขนาด | Key | คำอธิบาย |
| --- | --- | --- | --- | --- |
| user_id | INT | - | PK | รหัสผู้ใช้ (Auto Increment) |
| username | VARCHAR | 50 | UQ | ชื่อผู้ใช้สำหรับเข้าสู่ระบบ |
| password | VARCHAR | 255 | - | รหัสผ่าน (Hashed) |
| full_name | VARCHAR | 100 | - | ชื่อ-นามสกุล |
| role | ENUM | - | - | บทบาท: student, building_manager, technician, admin, reporter |
| phone | VARCHAR | 15 | - | เบอร์โทรศัพท์ |
| email | VARCHAR | 100 | - | อีเมล |
| created_at | DATETIME | - | - | วันที่สร้างบัญชี |
| updated_at | DATETIME | - | - | วันที่แก้ไขล่าสุด |

### Table: Buildings (อาคาร)

| ชื่อฟิลด์ | ชนิดข้อมูล | ขนาด | Key | คำอธิบาย |

### Use Case Description

#### UC-01: เข้าสู่ระบบ (Login)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-01 |
| **ชื่อ Use Case** | เข้าสู่ระบบ (Login) |
| **Actor** | ผู้ใช้ทุกคน |
| **Precondition** | ผู้ใช้มีบัญชีในระบบ |
| **Postcondition** | เข้าสู่ระบบสำเร็จ แสดงหน้าหลักตามบทบาท |
| **Main Flow** | 1. ผู้ใช้กรอกชื่อผู้ใช้และรหัสผ่าน 2. ระบบตรวจสอบความถูกต้อง 3. แสดงหน้าหลักตามบทบาท |
| **Alternative Flow** | ชื่อผู้ใช้หรือรหัสผ่านผิด → แสดงข้อความแจ้งเตือน |

#### UC-02: แจ้งปัญหา (Submit Repair Request)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-02 |
| **ชื่อ Use Case** | แจ้งปัญหา (Submit Repair Request) |
| **Actor** | นักเรียนนายเรืออากาศ |
| **Precondition** | ผู้ใช้เข้าสู่ระบบแล้ว |
| **Postcondition** | บันทึกการแจ้งปัญหาสำเร็จ สร้างเลขที่ใบแจ้งซ่อม |
| **Main Flow** | 1. เลือกอาคารและห้อง 2. เลือกประเภทปัญหา 3. กรอกรายละเอียด 4. แนบรูปภาพ 5. ยืนยันการแจ้ง 6. ระบบสร้างเลขที่ใบแจ้งซ่อมและบันทึก |
| **Alternative Flow** | ข้อมูลไม่ครบถ้วน → แสดงข้อความแจ้งเตือนให้กรอกข้อมูลเพิ่ม |

#### UC-03: ติดตามสถานะ (Track Status)

| รายการ | รายละเอียด |
| --- | --- |

| **ชื่อ Use Case** | ติดตามสถานะ (Track Status) |
| **Actor** | นักเรียนนายเรืออากาศ |
| **Precondition** | ผู้ใช้เข้าสู่ระบบแล้ว มีรายการแจ้งซ่อม |
| **Postcondition** | แสดงสถานะปัจจุบันของงานซ่อม |
| **Main Flow** | 1. เข้าสู่หน้ารายการแจ้งซ่อมของฉัน 2. เลือกรายการที่ต้องการ 3. แสดงสถานะและรายละเอียด |

#### UC-05: รับ/ปฏิเสธแจ้งซ่อม (Accept/Reject Request)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-05 |
| **ชื่อ Use Case** | รับ/ปฏิเสธแจ้งซ่อม (Accept/Reject Request) |
| **Actor** | ผู้ดูแลอาคาร |
| **Precondition** | มีรายการแจ้งซ่อมใหม่ที่ยังไม่ได้ตรวจสอบ |
| **Postcondition** | สถานะรายการเปลี่ยนเป็น "รับเรื่อง" หรือ "ปฏิเสธ" |
| **Main Flow** | 1. ดูรายการแจ้งซ่อมใหม่ 2. ตรวจสอบรายละเอียด 3. คัดกรองปัญหาซ้ำซ้อน 4. รับเรื่องหรือปฏิเสธ 5. บันทึกผลการตรวจสอบ |

#### UC-06: มอบหมายช่าง (Assign Technician)

| รายการ | รายละเอียด |
| --- | --- |
| **Use Case ID** | UC-06 |
| **ชื่อ Use Case** | มอบหมายช่าง (Assign Technician) |

| **Precondition** | รายการแจ้งซ่อมได้รับการรับเรื่องแล้ว |
| **Postcondition** | ช่างได้รับมอบหมายงาน สถานะเปลี่ยนเป็น "มอบหมายแล้ว" |
| **Main Flow** | 1. เลือกรายการแจ้งซ่อมที่รับเรื่องแล้ว 2. เลือกช่างที่เหมาะสม 3. ยืนยันการมอบหมาย 4. แจ้งเตือนไปยังช่าง |

| **Postcondition** | บันทึกผลการซ่อม สถานะเปลี่ยนเป็น "เสร็จสิ้น" |
| **Main Flow** | 1. เปิดงานที่ได้รับมอบหมาย 2. กรอกผลการซ่อม 3. บันทึกวัสดุที่ใช้ 4. ยืนยันการเสร็จสิ้น |
