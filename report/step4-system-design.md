# ส่วนที่ 4: การออกแบบระบบ (System Design)

---

## 4.1 User Interfaces

ระบบแจ้งซ่อมอาคารนอนออกแบบในรูปแบบ **Web Application แบบ Responsive (Mobile-first)** ที่เข้าถึงง่ายผ่านสมาร์ทโฟน แท็บเล็ต หรือคอมพิวเตอร์ โดยแต่ละหน้าจอออกแบบให้สอดคล้องกับกระบวนการทำงานจริงและบทบาทของผู้ใช้

### หน้าจอเข้าสู่ระบบ (Login Screen)

**คำอธิบาย:** หน้าจอเข้าสู่ระบบสำหรับผู้ใช้ทุกบทบาท กรอกชื่อผู้ใช้ (Username) และรหัสผ่าน (Password) เพื่อเข้าสู่ระบบ

**ส่วนประกอบ:**
- โลโก้ / ชื่อระบบ
- ช่องกรอก Username
- ช่องกรอก Password
- ปุ่ม "เข้าสู่ระบบ" (Login)
- ข้อความแจ้งเตือนกรณีกรอกข้อมูลผิด

**การใช้งาน:** ผู้ใช้กรอกข้อมูลและกดปุ่มเข้าสู่ระบบ ระบบจะตรวจสอบและนำไปยังหน้าหลักตามบทบาท

---

### หน้าจอหลัก (Home Screen)

**คำอธิบาย:** หน้าจอหลักหลังเข้าสู่ระบบ แสดงเมนูหลักและข้อมูลสรุปตามบทบาทของผู้ใช้

**ส่วนประกอบ (นักเรียนนายเรืออากาศ):**
- ชื่อผู้ใช้และบทบาท
- ปุ่ม "แจ้งปัญหาใหม่"
- รายการแจ้งซ่อมล่าสุดของฉัน (3-5 รายการล่าสุด)
- สถานะสรุป (รอตรวจสอบ, รับเรื่อง, กำลังซ่อม, ซ่อมเสร็จ)

**ส่วนประกอบ (ผู้ดูแลอาคาร):**
- ชื่อผู้ใช้และบทบาท
- จำนวนรายการแจ้งซ่อมใหม่ (Badge)
- ปุ่ม "รายการแจ้งซ่อมทั้งหมด"
- ปุ่ม "ออกรายงาน"
- สรุปสถานะงาน

**ส่วนประกอบ (ช่างซ่อม):**
- ชื่อผู้ใช้และบทบาท
- จำนวนงานที่ได้รับมอบหมาย
- ปุ่ม "งานของฉัน"
- สรุปสถานะงานที่รับผิดชอบ

---

### หน้าจอแจ้งปัญหา (Repair Request Form)

**คำอธิบาย:** ฟอร์มสำหรับนักเรียนนายเรืออากาศกรอกเพื่อแจ้งปัญหาความชำรุด

**ส่วนประกอบ:**
- เลือกอาคาร (Dropdown)
- เลือกห้อง (Dropdown กรองตามอาคาร)
- เลือกประเภทปัญหา (Dropdown: ไฟฟ้า, ประปา, โครงสร้าง, เฟอร์นิเจอร์, อื่นๆ)
- รายละเอียดปัญหา (Text Area)
- แนบรูปภาพ (Photo Upload, สูงสุด 3 รูป)
- ปุ่ม "ส่งแจ้งปัญหา" (Submit)
- ปุ่ม "ยกเลิก" (Cancel)

**การใช้งาน:** เลือกอาคาร→ห้อง→ประเภท→กรอกรายละเอียด→แนบรูป→กดส่ง ระบบจะสร้างเลขที่ใบแจ้งซ่อมและบันทึก

---

### หน้ายืนยันแจ้งซ่อม (Confirm Submission)

**คำอธิบาย:** หน้าจอแสดงผลยืนยันว่าการแจ้งปัญหาได้รับการบันทึกเรียบร้อย

**ส่วนประกอบ:**
- ข้อความยืนยัน "แจ้งปัญหาสำเร็จ"
- เลขที่ใบแจ้งซ่อม
- สรุปข้อมูลที่แจ้ง (อาคาร, ห้อง, ประเภท, รายละเอียด)
- ปุ่ม "กลับหน้าหลัก"
- ปุ่ม "ดูสถานะ"

---

### หน้าจอติดตามสถานะ (Track Status)

**คำอธิบาย:** หน้าจอแสดงสถานะปัจจุบันของรายการแจ้งซ่อม พร้อม Timeline

**ส่วนประกอบ:**
- เลขที่ใบแจ้งซ่อม
- สถานะปัจจุบัน (Badge สี)
- Timeline แสดงลำดับสถานะ: แจ้งปัญหา → รับเรื่อง → กำลังซ่อม → ซ่อมเสร็จ
- รายละเอียดงาน (อาคาร, ห้อง, ประเภท, วันที่แจ้ง)
- ข้อมูลช่างผู้รับผิดชอบ (ถ้ามอบหมายแล้ว)

---

### หน้าจอดูประวัติ (History List)

**คำอธิบาย:** หน้าจอแสดงรายการแจ้งซ่อมทั้งหมดของผู้ใช้

**ส่วนประกอบ:**
- รายการแจ้งซ่อมแบบ List/Card
- แสดง เลขที่, อาคาร/ห้อง, ประเภท, สถานะ, วันที่
- ตัวกรองตามสถานะและช่วงเวลา
- ปุ่ม "ดูรายละเอียด" ในแต่ละรายการ

---

### หน้าจอดูรายการแจ้งซ่อม (Request List - ผู้ดูแลอาคาร)

**คำอธิบาย:** หน้าจอสำหรับผู้ดูแลอาคารดูรายการแจ้งซ่อมทั้งหมดที่เข้ามาในระบบ

**ส่วนประกอบ:**
- รายการแจ้งซ่อมแบบ Table/List
- แสดง เลขที่, ผู้แจ้ง, อาคาร/ห้อง, ประเภท, สถานะ, วันที่
- ปุ่ม "รับเรื่อง" สำหรับรายการใหม่
- ปุ่ม "มอบหมายช่าง" สำหรับรายการที่รับเรื่องแล้ว
- ตัวกรองและค้นหา

---

### หน้าจอมอบหมายช่าง (Assign Technician)

**คำอธิบาย:** หน้าจอสำหรับผู้ดูแลอาคารเลือกช่างเพื่อมอบหมายงาน

**ส่วนประกอบ:**
- สรุปรายการแจ้งซ่อม (อาคาร, ห้อง, ประเภท, รายละเอียด)
- รายชื่อช่างที่พร้อมรับงาน (List/Radio)
- วันที่มอบหมาย
- ปุ่ม "ยืนยันการมอบหมาย"
- ปุ่ม "ยกเลิก"

---

### หน้าจอรับงาน/ทำงานของช่าง (Technician Work Screen)

**คำอธิบาย:** หน้าจอสำหรับช่างซ่อมดูงานที่ได้รับมอบหมายและบันทึกผลการซ่อม

**ส่วนประกอบ:**
- รายละเอียดงาน (อาคาร, ห้อง, ประเภท, ปัญหา, รูปภาพ)
- ปุ่ม "เริ่มงาน" (สถานะ → กำลังซ่อม)
- ช่องกรอกผลการซ่อม (Repair Result)
- ช่องกรอกวัสดุที่ใช้ (Material List + จำนวน + ราคา)
- ค่าใช้จ่ายรวม (Auto-calculate)
- ปุ่ม "ปิดงาน" (บันทึกผล วัสดุ และค่าใช้จ่าย พร้อมเปลี่ยนสถานะเป็น "ซ่อมเสร็จ")

---

### หน้าจอรายงาน (Report Screen)

**คำอธิบาย:** หน้าจอสำหรับผู้บังคับบัญชา/ฝ่ายธุรการดูรายงานสรุป

**ส่วนประกอบ:**
- ตัวกรองรายงาน (ช่วงเวลา, ประเภท, อาคาร)
- แผนภูมิสรุปจำนวนแจ้งซ่อมตามสถานะ
- แผนภูมิจำนวนแจ้งซ่อมตามประเภท
- ตารางสรุปค่าใช้จ่าย
- ปุ่ม "ดาวน์โหลดรายงาน" (PDF/Excel)

---

### หน้าจอจัดการผู้ใช้ (User Management - Admin)

**คำอธิบาย:** หน้าจอสำหรับผู้ดูแลอาคารจัดการข้อมูลผู้ใช้

**ส่วนประกอบ:**
- รายชื่อผู้ใช้ทั้งหมด (Table)
- ปุ่ม "เพิ่มผู้ใช้ใหม่"
- ปุ่ม "แก้ไข" / "ลบ" ในแต่ละรายการ
- ช่องค้นหา
- การกำหนดสิทธิ์ (Role Dropdown)

---

## 4.2 Interactive Prototype

### ข้อมูล Prototype

**เครื่องมือที่ใช้ — ขั้นตอนการออกแบบ (Design):** Figma — จัดทำ Wireframe และ UI Design ตามแนวคิด Mobile-first Responsive
**เครื่องมือที่ใช้ — ขั้นตอนการพัฒนา (Build):** HTML5, CSS3, JavaScript (Vanilla) — พัฒนาเป็น Interactive Web Application ที่ทำงานจริงใน Browser
**รูปแบบ:** Web Application (Mobile-first Responsive) รองรับสมาร์ทโฟน แท็บเล็ต และเดสก์ท็อป
**สถานะ:** เสร็จสมบูรณ์ — Interactive Web Prototype ทำงานได้จริงครบทุกบทบาท (ใช้ข้อมูลจำลอง/Mock Data)

### ทำไม Prototype จึงพัฒนาเป็น Web Application แทนการจำลองใน Figma

Figma เป็นเครื่องมือออกแบบที่มีความสามารถในการสร้าง Interactive Prototype ได้ระดับหนึ่ง แต่มีข้อจำกัดสำคัญคือ **ไม่สามารถรัน Logic จริงของระบบได้** ยกตัวอย่างเช่น เมื่อผู้ดูแลอาคารกดปุ่ม "รับเรื่อง" ใน Prototype ของ Figma จะได้เพียงแค่ Animation เปลี่ยนหน้าจอ แต่สถานะของรายการจะไม่ถูกบันทึกและไม่มีการเปลี่ยนจริง — นักเรียนที่ติดตามสถานะจะยังเห็นข้อมูลเดิมเสมอ

ทีมจึงเลือกพัฒนาเป็น **Web Application เขียนด้วย HTML/CSS/JavaScript (Vanilla)** โดยมี State Management ผ่าน LocalStorage เพื่อให้ได้ **Interactive Web Prototype** ที่หน้าจอและ Flow ทำงานได้จริงครบทุกบทบาท เช่น

- ผู้ดูแลอาคารกด **"รับเรื่อง"** → สถานะรายการเปลี่ยนเป็น "รับเรื่อง" ในระบบจริง
- มอบหมายช่าง → ช่างเห็นงานนั้นขึ้นในรายการ "งานของฉัน" ของตนเองทันที
- ช่างบันทึกผลแล้วกด **"ปิดงาน"** → สถานะเปลี่ยนเป็น "ซ่อมเสร็จ" และนักเรียนเห็น Timeline ครบทุกขั้นตอน

แนวทางนี้ทำให้ผู้ใช้หรือผู้ประเมิน **ทดสอบระบบได้เหมือนใช้งานจริง** ตั้งแต่ Login จนถึงออกรายงาน ก่อนย้ายไปเป็นระบบจริงที่มี Backend และฐานข้อมูลในระยะถัดไป โดยยังคงใช้ **Figma เป็นต้นแบบการออกแบบ UI** (Wireframe → Visual Design) เป็นขั้นตอนแรกของการพัฒนาหน้าจอแต่ละหน้า
